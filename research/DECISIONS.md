# Decisions

Each entry: what I decided, and why. Newest at the bottom.

- **D1. Ran the prompt, recorded first.** The chat message was only the pasted prompt, so I asked once whether to run it. The answer was "Run it, record first", so the 5-minute clip was recorded before the videos (still "before changing anything", as the prompt asks).
- **D2. Worktree from origin/main, upstream removed.** `git worktree add -b feat/classroom-vision ..\ARGOS-vision origin/main` (origin/main = 95f7811, the "remove desk boxes" merge). Git set the new branch to track origin/main; I ran `git branch --unset-upstream` so a stray `git push` can't go anywhere.
- **D3. Watch skill: Gemini failed, used the local engine.** The skill was configured for Gemini (key present). Attempt 1: gemini-3.7-flash HTTP 503 (overloaded), twice. Attempt 2: other models, gemini-2.5-flash 404 (retired), gemini-3.8-flash 503. After those 2 setup attempts I set up the local engine inside the sandbox (ffmpeg + ffprobe from the `ffmpeg-binaries` PyPI wheel, `yt-dlp` from PyPI, both in `.venv-sandbox`, put on PATH only for the watch process). All 8 videos then processed with captions + keyframes. I did not change `~/.config/watch/.env`.
- **D4. Watch detail = efficient, 16 frames per video, captions only.** Enough to confirm what each video shows; every video had captions, so no speech-to-text was installed. Where a claim rests only on captions I wrote "said"; where I saw it in a frame, "shown".
- **D5. Existing AGPL models kept for the baseline.** The repo already runs `yolo11n-pose.pt`, `yolo11n.pt`, `yolov8s-worldv2.pt` (Ultralytics, AGPL-3.0). The baseline must use them, so I copied them from the main checkout (read only) into `models\`. Any **new** model I download must be Apache-2.0 / MIT / BSD; AGPL does not count as "similar" for new downloads.
- **D6. Skipped graphify.** The repo is ~20 source files; I read the files directly. A graph would add an untracked `graphify-out/` folder to the branch for no gain.
- **D7. The clip came out at 3.85 camera fps, not 30.** The recorder asks for MJPG 1080p @ 30, but it encoded every frame to MJPG at quality 90 and drew a preview in the same thread, while the watch skill was decoding videos in the background. The user had left the camera by the time I saw the rate, so I kept the clip. Effect: frames are ~260 ms apart, so between-frame tracking is tested on bigger jumps than the live camera would give (harder, not easier). Timestamps per frame are in `classroom_times.json` and the brain is fed those real times.
- **D8. Ground truth = helper model + my own check, boxes only.** A bigger, separate detector (RT-DETRv2-R50, Apache-2.0, never used by the app) proposes person/phone boxes on the full frame and 6 overlapping tiles; I then check every review frame by eye and fix: remove false boxes, add missed people, and draw the items (watch, headphones, paper, pen, phone) by hand on a 200 px grid. Hand-drawn item boxes are rough, so an item counts as found if the boxes overlap (IoU >= 0.2) or the found box's centre is inside the true box grown by 30%. Only box numbers are stored (`research/labels/gt.json`), no pictures.
- **D9. Distance in metres is an estimate.** No calibration target was recorded. I estimated the camera focal length at ~900 px (the person at the desk, ~0.7 m away, has ~0.45 m of shoulders covering ~580 px), and convert a person box height h (px) to distance = 900 x 1.0 m / h (about 1.0 m of a seated person is visible). Bands: near < 2 m, mid 2-6 m, far > 6 m. Treat the metres as +/- 30%.
- **D10. OpenVINO telemetry turned off.** The `openvino` wheel pulls in `openvino-telemetry`; I ran `opt_in_out --opt_out` right after install so nothing is sent out (the prompt forbids sending data to outside services).
